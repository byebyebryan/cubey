01 / Current capability

The renderer is usable.
The editor is still being qualified.

There are two current native front doors: saved authored scenes and the material workshop. Saved construction playback already works. Continuous brush input is implemented in a separate, bounded test route.

Two different uses of “hybrid”

Rendering Hybrid uses cached bounds and source evaluation near surfaces to retain source detail.

The editing composition combines the committed Cached scene with recent analytic primitives. It can run with Cached as the rendering default; it does not require switching the whole scene to the public Hybrid mode.

What carried over from projectR

Capsule line segments, a committed/pending split and preserving source history were useful starting points. Independent endpoint radii extend the brush representation to tapered rounded segments.

Straight input can compact well; corners, curvature and width changes need more segments. That reduces brush-history growth, but does not remove Guardian’s existing source complexity.

“Exact update” means equal to a fresh Cached rebuild. Raw active R16 values and topology match the canonical sampled field. This does not turn Cached into analytical geometry or recover detail that was absent from the cache.
03 / What actually improved

Less preparation waste.
Better GPU work granularity.

Whole scenes were serialized and reparsed just to compare materials, then prepared again inside the builder. Removing that work helped. Coarser dispatches also made the GPU work itself cheaper.

What this trial proves

On the simple sphere, 35 poses at 120 Hz produce 15 accepted primitives; 67 poses at 240 Hz produce 14. Each 0.35-second input contains pauses, a corner, curvature, changing width and separate strokes.

All accepted IDs survive. The final source/history and raw cache match independent rebuilds. Dense reconstruction stays within the declared centerline-plus-radius tolerance.

The same-operation, fixed-palette route commits up to four primitives per job using two Fields. General long-running editing, mixed operations and a public UI are not established by this finite trace.

05 / What still matters

The remaining problem is
sustained capacity.

A fast frame is only one part of editing. We need enough source headroom, enough commit throughput, bounded queues and predictable completion under changing workloads.

Scene growth

Guardian is nearly full

1,011 leaves out of 1,024 leaves nominally leave only 13 primitive slots. The 65 authored history actions are not 1,011 separate brush actions. A stroke can consume several leaves, and depth/stack limits can bind earlier.

Service stability

The margin is empirical

Frozen calibration bounds underestimated some work. The final check measures actual availability and keeps overruns. We do not yet know why the slower Guardian classifier units appeared.

Integration

The public app is separate

The private incremental path still needs broader steady-input tests before UI adoption. Multiple GPU readers, grouped-stroke undo, queue saturation and long sessions remain open.

Memory and quality remain bounded too. Two Fields plus builder payload are about 1.71 GiB, excluding renderer/driver residency. Cached still has thin-feature and grazing/workspace-edge limitations. No allocator, center-cache or field-authoritative representation change was made in the last pass.
06 / Recommended next pass

Scale the proven loop
before adding more machinery.

The next useful question is how long this setup can keep up on a moderate authored scene. It is early to select a larger representation pivot, or to promise a Guardian sculpting tool.

1

Use a scene with headroom

Choose a moderate authored model and preflight its full input stream. Include live source construction, not just a pre-parsed four-edit batch.

Gate: source/depth/slot admission passes before timing starts.

2

Run sustained, bounded input

Keep 120/240 Hz poses, add/cut and width changes. Extend duration, pressure the queues and record every accepted ID, preview age and committed age.

Gate: exact cache/source, bounded backlog and declared frame/edit deadlines.

3

Revisit Guardian separately

Use a source-admitted workload and capture GPU workload/frequency observations around slower units. Keep 4/6/8 ms comparisons explicit.

Gate: explain or bound the miss before promoting a strict service claim.

When would a representation change become justified?

If full-source preparation/evaluation or retained-history growth dominates sustained editing, compare spatially reduced CSG programs with a sampled working field and separate history/checkpoints. Those are different quality/history contracts. A restricted classification-center cache also needs validity, initialization and exposed-child proofs. They remain research candidates, not adopted next steps.

This is a recommendation for a later bounded investigation. This overview does not start another implementation or GPU study.

The public executable and all 220 SPVs stayed unchanged in the last loop. Measured strict runtime: 9df0fa1f; final admission guard: f49f8070. No public editor, 90 Hz, physical-display latency or XR acceptance is claimed.

Reading the three clocks

Render cost: GPU time to draw an already prepared scene.
Frame completion: paced work plus drawing within the frame target.
Edit completion: accepted input until a completed draw uses the committed cache.

A scene can render quickly while cache construction is expensive. A responsive preview can also appear long before settling. Those are useful behaviors, with separate acceptance checks.
