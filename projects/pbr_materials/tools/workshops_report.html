What the SDF adapter adds

Four primitives form two smooth fused lobes, a toroidal groove and a through-cut. Shared coordinates continue across the joined surfaces and newly exposed cuts. Contrasting cut ownership and smooth material blending are independent appearance choices.

Glass transport intentionally differs. Mesh glass uses an explicit 0.5-unit thickness estimate. SDF glass follows measured interface segments with an eight-crossing budget and the retained environment/TIR fallback. Dark refracted/reflected regions can sample the physical lower hemisphere while the visible sky uses a horizon handoff. A CSG oblique diagnostic had zero capped/error pixels at both eight and sixteen crossings; raising the budget did not change its TIR classification.

The foundation boundary

Portable content

Strict versioned recipes store linear surface/optical values, deterministic procedural parameters and an affine material domain. The CPU and GLSL evaluators return color, roughness, emission and analytic height gradient. Gradients follow the domain Jacobian; unresolved detail is filtered.

Geometry-owned behavior

Meshes supply attributes and a thickness estimate. SDF supplies hit data, CSG ownership/blending and measured in-medium distances. Recipes contain no guardian tree, camera, exposure or weather.

Safe editing

Mesh editing uses one preallocated material table for each retired frame slot. Existing material tables stay immutable by default. Glass and opaque routes use permanent handles. Native UI checks covered lighting changes, save/reload and SDF cut/blend changes; files saved in either workshop cross-load/export unchanged in the other.

Preserved controls

All seven SDF sphere fingerprints match the inline catalog exactly. Four accepted SDF PNGs and furnace, IOR and glTF controls remain byte-identical. Full core tests, recipe/workshop tests, public headers, foundation boundaries, layout and navigation pass. The scoped documentation CLI audit covers 27 recipes.
