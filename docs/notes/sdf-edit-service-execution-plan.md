# Bounded edit-service execution

Date: 2026-11-01. Intake: `6e9bce4e` plus the completed
[solution research](sdf-interactive-edit-solution-research.md).
This is the authorized private implementation/measurement pass. Public Cached
defaults and all other render modes remain unchanged.

## Outcome and boundaries

Determine whether preparation and submission improvements can supply four
accepted edits within 66.667 ms while completing every paced 60 Hz frame within
16.67 ms. Record Guardian misses honestly; successful completion of this study
does not require declaring that model interactive. Run a finite timed-stroke
integration only for a scene/configuration that passes its service controls.

Keep exact raw R16/topology against independently rebuilt canonical source,
retained source/history/material semantics, eight pending primitives including
the tip, two Fields, one GPU owner and current capacity/resource screens.
Keep one completed draw at a time unless separate GPU-reader lifetime evidence
qualifies a wider boundary. CPU readiness is not GPU reader retirement.

No center cache, new representation, allocator, public brush/undo UI, smoothing,
domain modifiers, XR claim, push, publication or cleanup is authorized here.
Keep the previous qualified native, shader bundles, receipts and dumps intact.

## Frozen sequence

1. Preserve the research and this plan in a local commit before runtime edits.
2. Run the existing Release binary on Guardian/Robot add/cut, four pending
   spheres, 1080p SS1, 512 groups and 4 ms. Pair validation on/off with three
   repetitions, alternate order and calibrate separately. Keep identical source,
   SPVs, input and work checks; require exact canonical caches when drained.
3. Profile preparation stages. Compare the original full-document palette
   round trip against a palette-only identity, and duplicate preparation against
   a validator-created immutable owned result independently. Include copies and
   all new-edit preparation after receipt; no future edits prepared off-clock.
   Reject stale editor/base/palette/prefix versions, including undo/load ABA.
4. Instrument unit ready/grant/submit/completion times. Compare fixed dispatch
   sizes (512/1024/2048 groups), then a dependency-preserving pooled/bounded
   submission control if source inspection supports it. Preserve barriers,
   counter readbacks and work. Do not infer GPU speedup from host-only savings.
5. Keep 4 ms as control. Test explicit 6/8 ms maintenance allowances for the
   selected measured candidate, reporting complete-frame and replacement
   deadlines, overruns and queue age. Do not retry indefinitely after a miss.
6. If the selected route passes on a source-admitted modest scene, integrate a
   finite 120/240 Hz position/radius stream with bounded buffering, preview,
   commits and drain. Preflight source limits, preserve every accepted ID and
   release/restart gaps, and compare the settled result with canonical source.
   Keep Guardian as a separate stress result. Otherwise stop integration and
   record the failed gate and the next decision.

## Acceptance and evidence

- Preserve original public executable and 211 protected SPV hashes. Compile
  private study/test targets only; no broad rebuild of unrelated projects.
- Palette identity must match the original serializer for V2/V3, native edits,
  names/order, patterns, optics, material domains and library/recipe metadata.
- The immutable prepared path must be factory-only and deeply owned. Bind it
  to session/base/palette/prefix identity; stale/cancelled results do not publish.
  The existing revalidating path remains an independent control.
- Use add and cut, zero/sphere/rounded controls and numerical/failure cases.
  Strict native cache/topology equality is required before accepting a candidate.
- Validation-on correctness runs remain required. Validation-off performance
  does not count as an algorithmic improvement; report each mode separately.
- Retain source-pinned commands, logs, input hashes, runtime/shader identities,
  CPU/GPU stage timings, frame/job ages, work counts and a reproducible summary.
  Avoid bulk native dumps: retain representative canonical/local pairs only if
  new dumps are needed. Existing evidence is protected.
- Make narrow local implementation/evidence commits. Finish with results,
  limitations and an explicit next decision. A missed timing gate is a measured
  result; do not change quality, workload, accepted IDs or the clock to hide it.
